## Deploying

The app targets a serverless host with no writable filesystem and no git binary at request
time — Vercel is what it was built against. Nothing depends on either: ingest is GitHub
API work, and the committed snapshots are static imports rather than files read at
runtime.

1. Import the repository into the host and let it detect Next.js. The default
   `pnpm build` / `pnpm start` pipeline is correct; no custom build command is needed.
2. Set `GITHUB_TOKEN` and `ANTHROPIC_API_KEY` as **server-side** environment variables for
   the environments you want live analysis in. Do not prefix either with `NEXT_PUBLIC_`.
3. Optionally set `GRAIN_ANALYSIS_WINDOW_DAYS` and `GRAIN_MAX_PULL_REQUESTS` to narrow the
   work a single request may do.

Both API routes declare `export const runtime = 'nodejs'` — Octokit and the AI SDK do not
run on the Edge runtime — and an explicit `maxDuration`: 300 seconds for `/api/analysis`,
which is the ceiling Vercel's free tier allows and cannot be raised there, and 60 for
`/api/enrichment`, which is one model call.

**There are no background jobs.** A live analysis runs inside the request that asked for
it. Closing the tab ends it, a retry starts it over, and nothing is queued, stored or
resumed. The enrichment cache is in-memory and lives only as long as the serving instance
that holds it — a cold instance re-asks the model, which is a normal miss and not an
error.

Yes — the three optional ones you can skip entirely. But the split isn't 2-vs-3, it's really about which feature you want live:

Variable Skippable? If absent
GITHUB_TOKEN Yes, but /api/analysis returns 500: "Grain has no GitHub token configured, so it cannot read any repository."
ANTHROPIC_API_KEY Yes, but /api/enrichment returns 500: "Grain has no Anthropic key configured."
GRAIN_ANALYSIS_WINDOW_DAYS Yes Falls back to 90 days
GRAIN_MAX_PULL_REQUESTS Yes Falls back to 100
ENRICHMENT_MODEL Yes Falls back to the built-in model id

So nothing crashes and the build doesn't care — all five are read at request time, inside route handlers. Deploy with zero env vars and the site comes up fine: the four baked snapshots work, all three levels work, the whole of US1 is live. Only Other… breaks, and it breaks with a stated message rather than a blank screen.

The practical shape:

  • Want just the demo? Add nothing. US1 is fully working, and it's the P1 story.
  • Want Other… to work? Both keys are required — they're an all-or-nothing pair per feature. GITHUB_TOKEN alone gets you a live canvas where every change reads "Unenriched"; ANTHROPIC_API_KEY alone does nothing, since you can't reach enrichment without an analysis first.

One caveat on "technically": the defaults for the two GRAIN_* bounds are the permissive end — 90 days and 100 pull requests, which is where the concurrency ceiling issue bites. Skipping them is fine for a private or unshared URL. If the link is going anywhere public, they're the only throttle that exists today, so I'd set them low rather than take the defaults.
